# The embedded web client belongs to the binary build, not to the source tree

The manifest the Session Host serves the web client from is generated by
`scripts/build-binary.mjs` and injected at bundle time. `src/web/embedded.ts` exports an empty
`AssetManifest` and is the one module esbuild replaces, so the only build that embeds a web client is
the only build that carries one. `serve()` takes the manifest as a required `ServeOptions` field
rather than importing it, which leaves `src/daemon/server.ts` ignorant of where its assets came from
and `src/cli/main.ts` the single place a build output enters the program.

This revises ADR 0007, which had `src/web/assets.generated.ts` committed to the repository. That
decision was justified by the static import in `src/daemon/server.ts`: a fresh clone would not
typecheck until someone had run a bundler. The reasoning does not hold, because a static import
requires the module to be resolvable rather than tracked — a committed declaration satisfies tsc,
and the repository already used exactly that seam, since `src/web/assets.ts` is hand-written and
deliberately separate from the generated module. But the better objection is upstream of the
argument: `src/` should not import a build output at all, and once it does not, the question of how
to track one stops being asked.

Nothing about development changes, which is what makes the cost small. `web/vite.config.ts` proxies
`/api` and `/auth` to a Session Host started separately, so a developer already runs two processes
and reaches the client on the dev server; ADR 0007's own README section warns that following the
host's URL "lands you on the embedded bundle rather than on the dev server". The embedded copy inside
a source run was a third path nothing depended on, and it is now gone: `npm start` serves the API and
404s the UI. A user is unaffected, because a user has the binary.

Three alternatives were rejected. Committing a `.d.ts` and gitignoring the generated module works —
tsc resolves `./gen.ts` to `gen.d.ts` when the implementation is absent, and prefers the real file
when present — but it keeps a build artifact in the source tree and buys an ignore rule, a
hand-maintained declaration, a `prestart` hook and a doubled CI typecheck to defend a shape that
should not exist. A computed dynamic import hides the module from tsc, and hides it from esbuild
too, which would ship a binary serving nothing. A git merge driver that rebuilt the manifest on
conflict was written and tested and is unsound: merge drivers run while git is merging the index,
before the working tree settles, so on two branches editing `web/index.html` and `web/src/index.css`
the merge came out clean with the second side missing from the manifest entirely.

What this costs is that nothing typechecks the embedded manifest any more. ADR 0007 had tsc
compiling a 2.5 MB literal on every run; the generated module is now `JSON.stringify` of a plain
object, which cannot be syntactically invalid but is also never checked against `AssetManifest`. The
guarantee moved rather than vanished — `test/assets-embedding.test.ts` pins `manifestOf()` against a
tree it builds itself, covering the content types, the base64 boundary and the `immutable` rule that
the Session Host is entitled to assume — and `test/assets-fixture.ts` spells the same rules out by
hand so the HTTP tier can serve a manifest with no bundler present. Two of ADR 0007's three
staleness gates are gone with the staleness: `SOURCE_HASH` and `sourceHash()` are deleted, because a
digest that proves a committed file is not older than its sources has nothing to say about a file
generated during the build that consumes it, and CI's rebuild-and-diff step is deleted for the same
reason. The module-graph assertion survives, moved to `scripts/shared-modules.mjs`, and is now
exercised by a test rather than mirrored in one.

Removing the file does not shrink the repository — every historical blob stays in history, and the
win is entirely prospective. What ends is the conflict: the manifest was 2.5 MB of minified
JavaScript with base64'd wasm and fonts under content-hashed keys, so every branch touching `web/`
collided on it and the only correct resolution was to discard both sides and rebuild. The
`.gitattributes` stanza that made those conflicts survivable goes with it. A browser-driven test of
the shipped bundle remains the gap ADR 0007 named, and is still deferred rather than solved.
